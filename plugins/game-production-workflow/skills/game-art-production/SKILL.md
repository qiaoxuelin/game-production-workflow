# Game Art Production

## Core authority

Inside the active `game-production-system` task, consume core-owned intent/status, boundaries, operation, capabilities, paths, quality/maturity, evidence/reviewer requirements, and recovery.

The art Skill must not create or own `TASK`, `PLAN`, status, gate, approval, close, or lifecycle; self-approve golden or final passage; alter frozen state; invent boundaries; or promote artifacts/tests to authority.

## Select one operation

Load only the selected reference by default. Do not preload or chain another; return when the operation changes.

## Confirm input readiness and path safety

Confirm the brief/claim, frozen baseline, acceptance/stop conditions, viewports, evidence budget, authority, integrator, and paths. Return one clarification for a genuinely missing gameplay, interaction, state-ownership, protected-UX, product, or human/domain boundary. Precheck reversible unknowns.

Capture the dirty-worktree baseline. Preserve unrelated work and protected behavior, use only allowed paths/task scratch and named integrator, and checkpoint risky changes.

## Use honest capability fallback

Classify capabilities as `available`, `replaceable`, `installable`, or `final-fidelity-blocked`. Base tools and editable vector, code/procedural, project-native, or greybox sources qualify. Generated/external art is optional. Missing tooling preserves executable work and frozen planning: replace honestly or report the fidelity blocker, fallback, and recovery.

## Return one transient handoff

Return exactly one consolidated handoff for core mapping:

- `Operation`
- `Professional result`
- `Maturity assessment`
- `Fidelity disclosure`
- `Outcome or claim`
- `Changed paths`
- `Coverage`
- `Runtime proof`
- `Source and recovery`
- `Bulk unlock`
- `Unresolved risks`
- `Recommended next delta`

Map the transient result without taking ownership:

- Design `Proposed` remains non-`Ready` until the choice is core-recorded and design frozen; it grants no passage.
- `Implemented` remains/moves to `Implementing` and cannot close before acceptance.
- Review `Pass` or bounded pass is evidence only, never passage.
- `Returned` uses the existing `Result: Candidate returned — ...` recipe and normally stays `Implementing` while frozen repair criteria remain executable.
- `Blocked` moves to `Clarifying` only for a genuinely missing or changed human/domain boundary; otherwise preserve executable status, completed work, exact blocker, fallback, and recovery.

## Keep maturity and fidelity truthful

Use only `Direction`, `Production design`, `Runtime golden`, and `Integrated acceptance` as maturity. `Not established` and `Not applicable` report assessment absence; they are absence indicators, never maturity, fidelity, lifecycle, or passage.

Disclose fidelity as `Placeholder`, `Greybox`, `Working`, or `Final`; it never grants maturity. Echo `Integrated acceptance` only from core-recorded input. Otherwise report readiness/recommendation. Never infer runtime completion from art, source, mockup, or static proof.

## Bound the return

Finish the observable slice before polish. Make one root-cause repair batch and one regression. Stop after two no-evidence cycles or repeated cross-state regression; preserve passing work and return the blocker, evidence, fallback, recovery, and one next delta.
